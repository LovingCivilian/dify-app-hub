# App UI Internationalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every string a user or admin sees in the browser comes from i18next, in correct English and the original Chinese, and follows the language switch.

**Architecture:** All text moves into two JSON files (`locales/en/translation.json`, `locales/zh/translation.json`) loaded by the existing `libs/i18n.ts`. A type declaration makes unknown keys a compile error. Source files swap each hardcoded Chinese literal for a `t('key')` call and nothing else.

**Tech Stack:** Next.js 16 (App Router), React 19, i18next 25, react-i18next 16, i18next-browser-languagedetector 8, i18next-cli (new dev dependency), Ant Design 6, Vitest 4, oxlint, oxfmt, pnpm 11.

**Spec:** `docs/superpowers/specs/2026-10-01-app-ui-i18n-design.md`

## Global Constraints

- Branch: `i18n/app-ui`. Never commit to `main`.
- Translation files: `locales/en/translation.json` and `locales/zh/translation.json`, default namespace `translation`, keys nested by area in `area.snake_case`.
- Upstream's existing key names do not change.
- Chinese values are copied verbatim from the current source literals. English values are the ones given in this plan.
- No interpolation variable is named `count` (that name triggers i18next plural lookup). No plural keys are used; the English phrasing in this plan avoids them.
- Edits to upstream files are line-level: swap the string, add the import and the hook line, nothing else. No reformatting, renaming or tidying. The pre-commit formatter (`oxfmt`) may re-wrap a line that grew past 100 columns; that is acceptable.
- Replacement convention, used by every table below:
  - string literal `'中文'` → `t('key')`
  - JSX attribute `attr="中文"` → `attr={t('key')}`
  - JSX text `中文` → `{t('key')}`
  - anything else is spelled out in the table's "Replace with" column
- In tables, `\|` inside a code cell stands for the `|` character (escaped for the table).
- "Add the hook" means: add `import { useTranslation } from 'react-i18next'` to the imports (skip if present) and `const { t } = useTranslation()` as the first statement of the named component (skip if present).
- If a replaced string sits inside `useMemo`, `useCallback` or `useEffect` with a dependency array, add `t` to that array.
- Browser `console.*` messages become plain English in place, with no translation key.
- Line numbers refer to the file before this plan's edits (commit `e62c2b3`). Locate each string by its Chinese text; the number is a guide.
- Do not run `drizzle-kit push`, and do not start the dev server (repository `AGENTS.md`). Browser verification is done by the fork owner.
- Do not run `i18next-cli extract` or `i18next-cli sync`: they rewrite the JSON files and cannot see keys held in constants.
- Every commit message ends with these two trailer lines:
  ```
  Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_01RaL8KWES4BNuKBeqmvJ6T3
  ```
- The Chinese-text check used throughout (shows non-comment lines containing Chinese):
  ```bash
  git grep -nP '[\x{4e00}-\x{9fff}]' -- <paths> | grep -vP '^[^:]+:\d+:\s*(//|\*|/\*|\{/\*)'
  ```

## Review Focus

1. **Region-tagged browser languages** (`en-US`, `zh-CN`, `zh-TW`): the UI and Ant Design's built-in text must both land on English or Chinese, not a mix. Pinned by `__tests__/i18n-init.test.ts` (Task 1) and by using `i18n.resolvedLanguage` everywhere (Task 2, Task 6).
2. **Unsupported browser language** (`fr`, `ja`): the UI must fall back to English, never to raw keys. Pinned by `__tests__/i18n-init.test.ts` (Task 1).
3. **Non-string interpolation values** (an `Error` object passed as `{{error}}`): the message must show the error text, not `[object Object]`. Pinned by `__tests__/i18n-init.test.ts` (Task 1).
4. **Placeholder drift between languages** (`{{name}}` present in English but missing or misspelled in Chinese): would print raw braces or drop a value. Pinned by `__tests__/i18n-locales.test.ts` (Task 1).
5. **Switching language while a page is open**: labels that come from shared constants (menu, app types, theme modes) must change too, not stay in the old language. No component-test setup exists in this repo, so this is covered structurally (constants hold keys, `t()` runs at render; Tasks 2, 5, 6) and by the manual checklist in Task 8.

Create `__tests__/i18n-locales.test.ts`:

```ts
import { describe, expect, it } from 'vitest'

import en from '@/locales/en/translation.json'
import zh from '@/locales/zh/translation.json'

type Tree = { [key: string]: string | Tree }

const flatten = (tree: Tree, prefix = ''): Record<string, string> =>
	Object.entries(tree).reduce<Record<string, string>>((acc, [key, value]) => {
		const path = prefix ? `${prefix}.${key}` : key
		return typeof value === 'string'
			? { ...acc, [path]: value }
			: { ...acc, ...flatten(value, path) }
	}, {})

const placeholders = (text: string) => (text.match(/\{\{\w+\}\}/g) ?? []).sort()

const enFlat = flatten(en)
const zhFlat = flatten(zh)

describe('locale files', () => {
	it('define the same keys in en and zh', () => {
		expect(Object.keys(zhFlat).sort()).toEqual(Object.keys(enFlat).sort())
	})

	it('have no empty values', () => {
		const empty = [...Object.entries(enFlat), ...Object.entries(zhFlat)]
			.filter(([, value]) => value.trim() === '')
			.map(([key]) => key)
		expect(empty).toEqual([])
	})

	it('use the same interpolation placeholders in en and zh', () => {
		const mismatched = Object.keys(enFlat).filter(
			key => placeholders(enFlat[key]).join() !== placeholders(zhFlat[key] ?? '').join(),
		)
		expect(mismatched).toEqual([])
	})

	it('keep Chinese characters out of the English file', () => {
		const leaked = Object.entries(enFlat)
			.filter(([, value]) => /[一-鿿]/.test(value))
			.map(([key]) => key)
		expect(leaked).toEqual([])
	})

	it('never use "count" as an interpolation variable', () => {
		const offenders = Object.entries({ ...enFlat, ...zhFlat })
			.filter(([, value]) => value.includes('{{count}}'))
			.map(([key]) => key)
		expect(offenders).toEqual([])
	})
})
```

Create `__tests__/i18n-init.test.ts`:

```ts
import { afterAll, describe, expect, it } from 'vitest'

import i18n from '@/libs/i18n'

describe('i18n setup', () => {
	afterAll(async () => {
		await i18n.changeLanguage('en')
	})

	it.each([
		['en', 'en'],
		['en-US', 'en'],
		['zh', 'zh'],
		['zh-CN', 'zh'],
		['zh-TW', 'zh'],
		['fr', 'en'],
		['ja', 'en'],
	])('resolves %s to %s', async (language, expected) => {
		await i18n.changeLanguage(language)
		expect(i18n.resolvedLanguage).toBe(expected)
	})

	it('translates the same key in both languages', async () => {
		await i18n.changeLanguage('en')
		expect(i18n.t('common.cancel')).toBe('Cancel')
		await i18n.changeLanguage('zh')
		expect(i18n.t('common.cancel')).toBe('取消')
	})

	it('falls back to English text, not the raw key, for an unsupported language', async () => {
		await i18n.changeLanguage('fr')
		expect(i18n.t('auth.login')).toBe('Log in')
	})

	it('interpolates an Error object as its message', async () => {
		await i18n.changeLanguage('en')
		expect(i18n.t('app.fetch_list_failed', { error: new Error('boom') })).toBe(
			'Failed to load apps: Error: boom',
		)
	})

	it('defines the key the rename dialog already uses', async () => {
		await i18n.changeLanguage('en')
		expect(i18n.t('chat.rename_placeholder')).toBe('Enter a conversation name')
	})
})
```

````markdown
# i18n maintenance

All UI text lives in `locales/en/translation.json` and `locales/zh/translation.json`. Components read it with `t('area.key')` from `react-i18next`. Keys are type-checked: a key that is missing from the English file fails `tsc`.

## Adding or changing text

1. Add the key to both JSON files, under the matching area.
2. Use it with `t('area.key')`. Outside React components, use `i18next.t('area.key')`.
3. Run `pnpm test` (checks that both languages have the same keys and placeholders) and `pnpm exec tsc --noEmit`.

Do not name an interpolation variable `count`, and do not run `i18next-cli extract` or `i18next-cli sync`: they rewrite the JSON files and cannot see keys held in constants.

## After merging upstream

```bash
git fetch upstream
git merge upstream/main
pnpm install
```

Then look for Chinese text upstream added:

```bash
git grep -nP '[\x{4e00}-\x{9fff}]' -- 'app/**/*.tsx' 'app/**/*.ts' 'components' 'hooks' 'lib' ':!app/api' | grep -vP '^[^:]+:\d+:\s*(//|\*|/\*|\{/\*)'
pnpm i18n:lint
```

The `git grep` lists every non-comment line containing Chinese. `pnpm i18n:lint` lists hardcoded text between JSX tags (it also reports product names such as "Dify App Hub Platform", which are fine). For each new string, add a key to both JSON files and replace the literal with `t()`.

Lines the `git grep` is expected to print:

- `components/chat/i18n-switcher/index.tsx` and `components/chat/chat-layout.tsx`: `中文`, the language's own name.
- `components/chat/markdown-renderer/blocks/think-block.tsx`: `text.includes('思考')`, matching model output.
- `components/chat/chatbox/message/referrence.tsx`: text inside a commented-out block.
- Trailing code comments (for example in `components/chat/theme-config.ts`).
- Server-side files not yet translated: `app/app-management/actions.ts`, `lib/mail.ts`, `lib/auth.ts`.

## Typical merge conflicts

- `libs/i18n.ts`: upstream added or changed inline strings. Keep this fork's version of the file and move upstream's new strings into the two JSON files.
- A line where upstream edited a string this fork replaced with `t()`: keep the `t()` call and update the JSON value.
- `package.json` / `pnpm-lock.yaml`: keep both sides in `package.json`, then run `pnpm install`.
````

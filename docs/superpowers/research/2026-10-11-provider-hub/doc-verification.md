Installed versions: `drizzle-orm` and `drizzle-kit` 1.0.0-rc.3, `zod` 4.6.5, `next` 16.3.x, PostgreSQL 18 docs (18.6). ## Deviations and suggested changes, ranked by impact

1. **Email equality lookups (3c), high: sign-in breaks without it.** Every lookup by email becomes `eq(lower(users.email), sql\`lower(${email})\`)`, with a shared `lower()`helper as in Drizzle's guide. Put`lower()`on both sides in SQL, as PostgreSQL's citext page writes it, rather than JS`toLowerCase()`on the value as Drizzle's guide does. That way the value goes through the same function as the index (the official image's default locale is`en_US.utf8`). Call sites: `lib/auth/options.ts:32`, `lib/data/users.ts:198`, `lib/data/directory.ts:100`, `app/api/auth/forgot-password/route.ts:30`. Record one behaviour change: MySQL's `utf8mb4_0900_ai_ci`also ignored accents, and`lower()` does not.
2. **Pool error listener (1b), high: a database restart can crash the hub.** In `db/index.ts`, build the pool explicitly: `const pool = new Pool({ connectionString })`, then `pool.on('error', …)` logging through `lib/error-log.ts`, then `drizzle({ client: pool, logger })`. Keep the existing `globalThis` singleton.
3. **Client registry across the server/client boundary (9b, 9c), medium-high: the planned shape would throw at render.** Pick shape (a) or (b) from row 9b and write it into the Part 1 spec. Shape (a), one client switch keyed by the provider id, also serves the gallery and the admin form. Rename the registry's folder, for example `components/app-types/` or `components/provider-kinds/`, so that `components/providers/` keeps meaning React context providers.
4. **The provider `pgEnum` and the one-transaction migrator (2e), medium: Part 2's migration can fail.** Either keep `pgEnum` and add a rule to the spec: a migration that adds an enum value ships in a deploy where no migration uses that value (no default, backfill, seed or CHECK that names it). Or store `provider` as `text` with a `check()` listing the ids. A CHECK is plain transactional DDL, has no ADD VALUE limit and allows removal; the cost is a drop-and-add of the constraint per provider. Both are documented. The reference hubs keep the type as a string validated in code. The same caveat applies to the other enums (`role`, `source`, `access_mode`).
5. **The volume path and shared memory for `postgres:18` (7b, 7c, 7d), medium: data is lost when the container is re-created.** Mount `pgdata:/var/lib/postgresql`, not `/var/lib/postgresql/data`. Set `shm_size: 128mb`. Use the Compose docs' healthcheck, optionally with `-h 127.0.0.1`.
6. **Indexes on referencing columns (row 12), medium-low: slow deletes and sign-ins as the data grows.** Add `index().on(t.groupId)` to `app_group_grants`, and `index().on(t.userId)` to `app_user_grants` and `user_group_members`. Check the other FKs the same way (`password_reset_tokens.user_id` already has an index).
7. **The isolation levels and the deadlock code (5a), low-medium.** Remove `isolationLevel: 'repeatable read'` from `createOwner` (`lib/data/setup.ts:62`). Its reason was InnoDB's gap lock; on PostgreSQL the partial unique index is the guarantee, and PostgreSQL's Repeatable Read adds `40001` failures that callers "must be prepared to retry" (https://www.postgresql.org/docs/18/transaction-iso.html). The sign-in's explicit `'read committed'` is PostgreSQL's default ("Read Committed is the default isolation level in PostgreSQL"), so it can stay or go. `isDeadlock` becomes `40P01`. Rewrite the MySQL-specific comments (gap locks, `FOUND_ROWS`, `max_allowed_packet`) for PostgreSQL. The 65,535-parameter bound per statement holds for PostgreSQL too (the Bind message counts parameters in an Int16, https://www.postgresql.org/docs/18/protocol-message-formats.html), so the 1,000-id batches stay.
8. **`ON CONFLICT` in place of catching duplicates (6), low.** Use `onConflictDoNothing({ target: directorySyncRuns.slot }).returning({ id })` for the slot claim. For the sync's membership batch inserts, `onConflictDoNothing()` skips duplicates without the row-by-row fallback; a foreign-key `23503` still raises. Change the settings upserts' `onDuplicateKeyUpdate` (`lib/data/settings.ts:145,155`) to `onConflictDoUpdate({ target, set })`; this one is required, because pg-core has no `onDuplicateKeyUpdate`. Not on the README's re-derivation list.
9. **Timestamp precision (2b), low.** Use `timestamp({ withTimezone: true, mode: 'date' })` with `.defaultNow()` and no `precision`, per the wiki and LobeHub.
10. **Concurrent migrations when scaling out (1d), low for now.** The installed `migrate()` has no lock. Two hub containers starting together race; the loser fails `set -e` and restarts. If several containers are ever run, use the documented Compose option: a one-shot `migrate` service that the app services wait on with `depends_on: { migrate: { condition: service_completed_successfully } }` (https://docs.docker.com/compose/how-tos/startup-order/).
11. **Column types the README leaves open, low (a GAP the port has to settle).** The wiki's "Don't use varchar(n) by default" applies to every `varchar(255)`: use `text`, with a CHECK where a limit matters, and keep the zod `.max()` (ADR-0025). For the UUID ids, PostgreSQL's `uuid` type (https://www.postgresql.org/docs/18/datatype-uuid.html; Drizzle `uuid()`) is the documented type. Its cost: a non-UUID string in a query raises `22P02 invalid_text_representation` instead of matching nothing, so every id from a URL needs `z.uuid()` first (some already have it, as in `app/(admin)/app-management/actions.ts:20`), or `22P02` maps to "not found". `text` ids avoid that and give up the type check.
12. **`drizzle-orm/zod` (8c), optional.** It is documented, but the per-provider zod schemas in the registry stay the validation. Leave the `jsonb` columns as `unknown` (no `.$type<…>()`), or as a generic record, so that the only typed value is the one a zod parse returns.
13. **Secrets column type at encryption time (10), a note for later.** An encrypted document is not JSON: LobeHub's `key_vaults` and Dify's `encrypted_config` are text. When encryption lands, plan for `secrets` to change type, or to hold `{ "ciphertext": … }` inside the `jsonb`.

1. **Blocking — Task 2 deletes `lib/password-reset.ts` while `e2e/auth.spec.ts` imports it.** `task-2-brief.md` Step 9: "`git rm lib/auth.ts lib/password-reset.ts __tests__/session-user.test.ts`"; `e2e/auth.spec.ts:5` is `import { hashPasswordResetToken } from '../lib/password-reset'`. `tsconfig.json` includes `**/*.ts` (e2e is type-checked), so Step 12's `pnpm exec tsc --noEmit` fails, and Step 12's `pnpm exec playwright test e2e/auth.spec.ts` fails to load the spec. Re-pointing the import at `../lib/auth/password` is not enough on its own: that file starts with `import 'server-only'` and no `server-only` package exists at `node_modules/server-only` (only Next's compiled copy and Task 1's vitest alias), so Playwright's Node loader cannot resolve it. Smallest correction: Task 2 edits `e2e/auth.spec.ts` to import from `../lib/auth/password` and `lib/auth/password.ts` omits `import 'server-only'` (it holds no secrets; its callers are server files), or the spec computes `createHash('sha256').update(token).digest('hex')` itself and `password.ts` keeps the guard. Add the spec to Task 2's Files list and `git add`.

2. **Blocking — the route tests' `params()` helper does not type-check against `RouteContext` with a second segment (Tasks 8, 9, 10).** `task-8-brief.md` Step 1: "`const params = (extra: Record<string, string> = {}) => ({ params: Promise.resolve({ appId: 'app-1', ...extra }) })`", then "`stopChat(json(…), params({ taskId: 't1' }))`" (same helper in `task-9-brief.md` and `task-10-brief.md`, used with `messageId`, `conversationId`, `workflowRunId`, `formToken`, `fileId`, `annotationId`). Spreading `Record<string, string>` yields `Promise<{ appId: string }>`, and `RouteContext<'/api/dify/[appId]/chat-messages/[taskId]/stop'>` is `{ params: Promise<{ appId: string; taskId: string }> }`; verified with tsc: "Property 'taskId' is missing in type '{ appId: string; }'".
